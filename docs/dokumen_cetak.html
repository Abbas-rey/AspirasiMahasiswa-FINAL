1. Gambaran Umum Sistem

ASMA (Aspirasi Mahasiswa) adalah platform web terpadu resmi civitas akademika UIN Syarif Hidayatullah Jakarta yang dirancang untuk menyampaikan aspirasi, keluhan fasilitas, masukan akademik, dan saran perbaikan langsung kepada unit kerja terkait secara aman, terstruktur, transparan, dan akuntabel.

Fitur Utama: Mendukung pengaduan berjenjang (Jurusan, Fakultas, Universitas), mode transparansi identitas ganda (Transparan vs Anonim), multi-lampiran bukti hingga 5 berkas (JPG/PNG/PDF/WEBP maks 10MB) serta tautan Google Drive, pembatalan mandiri (*Self-Service Delete*) oleh mahasiswa, pembatasan sesi maksimal 2 perangkat aktif (FIFO), dan auto-logout 1 jam inaktivitas.

2. Functional Requirements (Kebutuhan Fungsional)

2.1 Modul Autentikasi & Keamanan Sesi (FR-AUTH)

Kode FR Deskripsi Kebutuhan Fungsional Aktor Prioritas
FR-AUTH-01 Otentikasi pengguna berbasis NIM (Mahasiswa), NIP (Dosen/Akademisi), atau Username (Admin) dengan kata sandi terenkripsi Bcrypt (Salt rounds 10). Semua Role High
FR-AUTH-02 Pembatasan sesi login simultan maksimal 2 perangkat aktif per akun pengguna. Jika perangkat ke-3 masuk, sistem secara otomatis mencabut (evict) sesi pada perangkat terlama (FIFO). Semua Role High
FR-AUTH-03 Pemantauan aktivitas dan otomatisasi logout apabila pengguna tidak melakukan aktivitas (idle) selama 1 jam (60 menit), dilengkapi modal hitung mundur (countdown) pada menit ke-58 dan sinkronisasi lintas-tab. Semua Role High
FR-AUTH-04 Kewajiban mengganti kata sandi bawaan sistem (Uin<NIM/NIP>) pada saat login pertama dengan 6 kriteria keamanan kata sandi (panjang min 8 karakter, huruf besar, huruf kecil, angka, simbol, tanpa spasi) dan opsi tunda (Nanti). Semua Role High
FR-AUTH-05 Mekanisme Rate Limiting perlindungan terhadap serangan brute-force pada rute login (maksimal 10 percobaan gagal per 5 menit per alamat IP). Publik / Pengguna High
FR-AUTH-06 Pencabutan sesi secara aman melalui endpoint logout yang menghapus cookie sesi asma_session dan menghapus entri sesi pada tabel UserSession di database. Semua Role High

2.2 Modul Pengajuan Aspirasi (FR-ASP)

Kode FR Deskripsi Kebutuhan Fungsional Aktor Prioritas
FR-ASP-01 Penyediaan formulir pengajuan ringkas 1 halaman yang mencakup judul, deskripsi kejadian, kategori (Akademik, Dosen, Fasilitas, Administrasi, Sarpras, Lainnya), jenjang tujuan (Jurusan, Fakultas, Universitas), serta tanggal dan jam insiden. Mahasiswa High
FR-ASP-02 Pilihan mode privasi pengajuan: Mode Transparan (identitas pelapor terbuka) dan Mode Anonim (Nama, NIM, dan email disensor otomatis oleh sistem menjadi Mahasiswa (Anonim)). Mahasiswa High
FR-ASP-03 Dukungan unggah berkas bukti aspirasi hingga maksimal 5 berkas dengan ukuran maksimal 10 MB per berkas untuk format JPG, PNG, PDF, dan WEBP. Mahasiswa High
FR-ASP-04 Validasi tanda tangan berkas biner (deep magic bytes) di sisi server untuk menjamin keaslian tipe berkas dan mencegah serangan injeksi skrip atau executable berbahaya. Sistem Backend High
FR-ASP-05 Penyediaan kolom tautan penyimpanan cloud (Google Drive / OneDrive) sebagai bukti pendukung eksternal tanpa batasan kuota berkas fisik. Mahasiswa Medium
FR-ASP-06 Penerbitan Kode Tiket pelacakan acak unik terstruktur dengan format ASP-YYYY-XXXXXX (contoh: ASP-2026-004812). Sistem Backend High

2.3 Modul Pelacakan Publik & Dasbor (FR-TRK, FR-MHS, FR-AKAD, FR-ADM)

Kode FR Deskripsi Kebutuhan Fungsional Aktor Prioritas
FR-TRK-01 Pelacakan status tiket pengaduan secara publik berbasis Kode Tiket tanpa mengharuskan login, menyajikan visualisasi timeline progres dan riwayat catatan tindak lanjut. Publik / Civitas High
FR-MHS-01 Dasbor pribadi mahasiswa untuk memantau seluruh riwayat pengaduan yang diajukan beserta status terkininya. Mahasiswa High
FR-MHS-02 Fitur pembatalan / hapus mandiri (Self-Service Delete) aspirasi oleh mahasiswa pemilik sah dilengkapi modal konfirmasi, proteksi Anti-IDOR, dan auto-unlink berkas fisik storage. Mahasiswa High
FR-AKAD-01 Dasbor pejabat peninjau yang secara otomatis menyaring aspirasi masuk berdasarkan lingkup wewenang akademisi (Jurusan, Fakultas, atau Universitas). Akademisi High
FR-AKAD-02 Pembaruan tahapan status aspirasi (DITERIMA → DIPROSES → DITINDAKLANJUTI → SELESAI) beserta catatan progres dan publikasi tanggapan resmi. Akademisi High
FR-ADM-01 Dasbor administrator yang menyajikan metrik agregat statistik kampus, manajemen CRUD pengguna, dan Bulk Import akun civitas via format berkas CSV/Excel. Administrator High

4. Activity Diagram (Diagram Aktivitas)

4.1 Alur Pengajuan Aspirasi oleh Mahasiswa

flowchart TD
    Start([Mulai]) --> BukaForm[Buka Halaman /ajukan]
    BukaForm --> IsiData[Isi Judul, Deskripsi, Kategori, Jenjang, Waktu]
    IsiData --> PilihMode{Mode Privasi}
    PilihMode -- "Transparan" --> SetTrans[Identitas Terbuka]
    PilihMode -- "Anonim" --> SetAnon[Identitas Disensor Sistem]
    
    SetTrans --> Lampirkan[Unggah Berkas Bukti maks 5 file & Link GDrive]
    SetAnon --> Lampirkan
    
    Lampirkan --> Submit[Klik Kirim Aspirasi]
    Submit --> ValBytes{Validasi Magic Bytes}
    ValBytes -- Gagal --> TolakFile[Tolak Berkas Palsu]
    TolakFile --> Lampirkan
    
    ValBytes -- Berhasil --> GenCode[Generate Tiket ASP-YYYY-XXXXXX]
    GenCode --> SimpanDB[(Insert Aspirasi & StatusLog ke Supabase)]
    SimpanDB --> Sukses[Arahkan ke Halaman Sukses]
    Sukses --> End([Selesai])

4.2 Alur Batas 2 Perangkat Aktif (Concurrent Device Limit FIFO)

flowchart TD
    Start([Login dari Perangkat Baru]) --> CekValid{Kredensial Valid?}
    CekValid -- Tidak --> ErrorLogin[Tampilkan Error Login]
    
    CekValid -- Ya --> CekJumlah[(Query Sesi Aktif di UserSession)]
    CekJumlah --> EvaluasiJml{Sesi Aktif >= 2?}
    
    EvaluasiJml -- "Ya (Sudah 2 Perangkat)" --> HapusLama[Hapus Sesi Terlama / FIFO]
    HapusLama --> HapusDB[(DELETE Oldest Record di Supabase)]
    HapusDB --> CreateSesi
    
    EvaluasiJml -- "Tidak (< 2 Perangkat)" --> CreateSesi[Buat Record Sesi Baru]
    CreateSesi --> SimpanSesi[(INSERT Sesi Baru ke Supabase)]
    SimpanSesi --> SignToken[Sign JWT & Set Cookie asma_session]
    SignToken --> BukaWeb[Masuk ke Dasbor]
    
    subgraph "Perangkat Terlama yang Ter-evict"
        Perangkat1[Perangkat Lama Mengakses Halaman / Tab] --> CekSesiAPI[Request ke /api/auth/me]
        CekSesiAPI --> CekDB{Record Ada di DB?}
        CekDB -- Tidak Ada --> ClearCookie[Hapus Cookie asma_session]
        ClearCookie --> RedirectLimit[Redirect ke /login?reason=device_limit]
        RedirectLimit --> Banner[Tampilkan Banner: Batas Maksimal 2 Perangkat]
    end

4.3 Alur Auto-Logout Inaktivitas 1 Jam

flowchart TD
    Start([Pengguna Aktif di Web]) --> Listen[Pasang Listener: Gerakan Mouse, Ketikan, Klik, Scroll]
    Listen --> TimerLoop{Interval Pemantauan Tiap 2 Detik}
    
    TimerLoop --> AdaAktivitas{Ada Input Pengguna?}
    AdaAktivitas -- Ya --> ResetTimer[Update asma_last_activity = Date.now]
    ResetTimer --> TimerLoop
    
    AdaAktivitas -- Tidak --> CekElapsed{Durasi Diam}
    CekElapsed -- ">= 58 Menit (Sisa 2 Menit)" --> ShowWarning[Munculkan Modal Peringatan Countdown]
    ShowWarning --> KlikPerpanjang{Klik 'Tetap Masuk'?}
    KlikPerpanjang -- Ya --> ResetTimer
    KlikPerpanjang -- Tidak --> CekElapsed
    
    CekElapsed -- ">= 60 Menit (1 Jam Penuh)" --> DoLogout[Panggil API /api/auth/logout]
    DoLogout --> RedirectInactivity[Redirect ke /login?reason=inactivity]
    RedirectInactivity --> End([Selesai])

5.2 Sequence: Pembatasan Maksimal 2 Perangkat (Device Eviction)

sequenceDiagram
    autonumber
    actor D3 as Perangkat 3 (Baru)
    participant API as API (/api/auth/login)
    participant SESS as Session Manager (session.ts)
    participant DB as PostgreSQL (Supabase)
    actor D1 as Perangkat 1 (Terlama)

    Note over D1,DB: Akun sedang aktif di Perangkat 1 & Perangkat 2 (Total = 2)
    D3->>API: POST /api/auth/login (NIM & Password)
    API->>SESS: createSessionForUser(user)
    SESS->>DB: SELECT * FROM UserSession WHERE user_id = user.id
    DB-->>SESS: Ditemukan 2 Sesi [Device 1, Device 2]
    SESS->>DB: DELETE FROM UserSession WHERE id = Device 1 (FIFO Eviction)
    SESS->>DB: INSERT INTO UserSession (Device 3)
    DB-->>SESS: Sesi Device 3 Tersimpan
    SESS-->>API: Token JWT Berisi session_id_baru
    API-->>D3: 200 OK + Set Cookie asma_session (Login Berhasil)

    Note over D1,DB: Perangkat 1 Mencoba Beraktivitas
    D1->>API: GET /api/auth/me (Membawa Cookie Lama)
    API->>DB: SELECT FROM UserSession WHERE token_id = session_id_device_1
    DB-->>API: Tidak Ditemukan (Sudah Dihapus)
    API-->>D1: 401 Unauthorized { reason: "device_limit" } + Clear Cookie
    D1-->>D1: Redirect ke /login?reason=device_limit

6. Entity Relationship Diagram (ERD) & Kamus Data

Diagram hubungan entitas (ERD) memetakan seluruh tabel, kolom, relasi, dan kardinalitas yang diimplementasikan pada database PostgreSQL (Supabase) via Prisma ORM.

erDiagram
    User ||--o{ UserSession : "has (max 2 active)"
    User ||--o{ Aspiration : "submits"
    User ||--o{ Response : "writes"
    Category ||--o{ Aspiration : "categorizes"
    Aspiration ||--o{ Attachment : "contains (max 5)"
    Aspiration ||--o{ StatusLog : "tracks"
    Aspiration ||--o{ Response : "receives"

    User {
        String id PK "UUID"
        String nim_nip UK "NIM / NIP / Username"
        String name "Nama Lengkap"
        String email UK "Email Akun"
        String password_hash "Bcrypt Hash"
        Role role "MAHASISWA | AKADEMISI | ADMIN"
        TargetLevel scope_level "JURUSAN | FAKULTAS | UNIVERSITAS"
        Boolean must_change_pwd "Wajib ganti password"
        DateTime created_at "Waktu dibuat"
    }

    UserSession {
        String id PK "UUID"
        String user_id FK "Relasi ke User"
        String token_id UK "Unique Session Identifier"
        String device_info "Browser & OS Pengguna"
        String ip_address "Alamat IP"
        DateTime last_active "Waktu aktif terakhir"
        DateTime created_at "Waktu sesi dibuat"
    }

    Category {
        Int id PK "Autoincrement"
        String category_name UK "Nama Kategori"
        String description "Keterangan"
    }

    Aspiration {

        String ticket_code UK "Kode Tiket Unik"

        String title "Judul Aspirasi"
        String description "Deskripsi Peristiwa"
        TargetLevel target_level "JURUSAN | FAKULTAS | UNIVERSITAS"
        AspirationStatus current_status "DITERIMA | DIPROSES | DITINDAKLANJUTI | SELESAI"
        DateTime incident_date "Tanggal Kejadian"
        String incident_time "Waktu Kejadian"
        Boolean is_anonymous "Flag Mode Anonim"
        String drive_link "URL Google Drive"
        DateTime created_at "Waktu Pengajuan"
    }

    Attachment {
        String id PK "UUID"
        String aspiration_id FK "Relasi ke Aspirasi"
        String file_name "Nama Asli Berkas"

        String file_type "MIME Type Berkas"
        Int file_size "Ukuran Berkas (Maks 10MB)"

    StatusLog {
        String id PK "UUID"

    }
